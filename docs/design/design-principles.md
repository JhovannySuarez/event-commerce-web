# Event Planner Design Principles

> **Plan your event. We'll take care of the rest.**

Our mission is to make event planning simple, enjoyable, and stress-free.
Every design decision should support that mission.

---

# 1. The Event Comes First

Users do not come looking for a venue.

They come because they want to organize an event.

Every screen should focus on helping users plan their event rather than navigating a catalog.

✅ Good

"What would you like to celebrate?"

❌ Bad

"Select a venue."

---

# 2. One Question Per Screen

Every screen should answer one single question.

This reduces cognitive load and makes the experience feel natural.

Examples

Screen 1

"What would you like to celebrate?"

Screen 2

"How many guests are you expecting?"

Screen 3

"When will your event take place?"

Never ask for too much information at once.

---

# 3. Guide, Don't Overwhelm

The application should feel like a personal assistant,
not like an administrative system.

Instead of displaying dozens of filters,
guide users step by step.

The platform should always suggest the next best action.

---

# 4. Conversations Over Forms

Whenever possible,
replace traditional forms with conversational interactions.

Users should feel like they are planning an event,
not filling out paperwork.

---

# 5. Recommendations Instead of Searching

Users should not have to know which venue is right.

The platform should recommend the best venues based on:

- Event type
- Number of guests
- Location
- Date
- Budget (future)

The user chooses among recommendations,
not from an endless catalog.

---

# 6. Simplicity is a Feature

Remove everything that does not help users achieve their goal.

Every component should have a purpose.

If something can be removed without affecting the experience,
it probably should.

---

# 7. Build Trust

Planning an event involves important decisions.

The interface must always communicate confidence.

We achieve this through:

- Clear information
- Honest pricing
- Ratings and reviews
- Availability
- Transparent policies

---

# 8. Beautiful but Functional

Beauty should support usability.

Visual design should never make the product harder to use.

Every animation,
color,
image,
and interaction
must have a purpose.

---

# 9. Mobile First

Many users will discover venues from their phones.

Every feature must provide an excellent mobile experience before considering desktop enhancements.

---

# 10. Accessibility by Default

The platform should be usable by everyone.

We will follow accessibility best practices whenever possible.

Examples

- Keyboard navigation
- Screen reader support
- Sufficient color contrast
- Large touch targets

---

# 11. AI as an Assistant

Artificial Intelligence is not the product.

It is the assistant.

The AI should guide users through the planning process,
provide recommendations,
and reduce decision fatigue.

The user always remains in control.

---

# 12. Consistency Above Creativity

A familiar experience is better than an inconsistent one.

Buttons,
cards,
colors,
spacing,
and interactions
must remain consistent throughout the application.

Consistency builds confidence.

---

# Final Principle

Every new feature must answer one question:

**Does this help users organize their event more easily?**

If the answer is no,
the feature should be reconsidered or postponed.
